# Verification Engine

The Verification Engine is a core backend component responsible for validating user-submitted evidence for sustainable actions.

## Principles
1. **Zero Client Trust**: The client is untrusted. Verification, AI analysis, and state transitions happen strictly on the server.
2. **Authoritative Timestamps**: Action timestamps are generated by the server at the time of receipt.
3. **AI Assistance, Not Autonomy**: AI analyzes evidence as **one signal only**; AI can NEVER directly award Green Points or mark a submission `VERIFIED` on its own.
4. **Safe Failure**: Any AI failure (timeout, network error, HTTP 429 rate limit, HTTP 500 server error, malformed response, low confidence) safely transitions to `REVIEW_REQUIRED`. It must never accidentally produce `VERIFIED` or award points.
5. **Authenticity & Fraud Risk**: Evidence is analyzed not only for semantic relevance to the action, but also for visual fraud indicators (AI-generated/synthetic imagery, digital manipulation/compositing, screen-of-screen recapture).

## States
An Action Submission can be in one of four states:
- `PENDING`: Initial state upon submission creation, awaiting evidence upload and finalization.
- `REVIEW_REQUIRED`: Signals were inconclusive, AI confidence was below threshold, AI fraud/authenticity flags were raised, AI provider failed/timed out, or soft checks (like geofencing) failed. Awaiting manual administrative review.
- `VERIFIED`: Evidence confirmed by all required automated signals (AI relevance + low fraud risk + geofencing + timestamp bounds + non-duplicate). Points awarded transactionally.
- `REJECTED`: Evidence deemed invalid, duplicate, fraudulent, or showing severe timestamp discrepancies. No points awarded.

## Verification Pipeline & Signals

```text
ActionSubmission (Finalized)
       │
       ▼
VerificationService
       │
       ├─► 1. SHA-256 Duplicate Check (Database unique constraint on file hash)
       │       └── Match found ──► REJECTED
       │
       ├─► 2. Server-side Timestamp Bounds (within 24 hours of action)
       │       └── Clock drift / extreme delay ──► REJECTED
       │
       ├─► 3. Geofencing Evaluation (Haversine distance <= campus zone radius)
       │       └── Outside zone / missing location ──► REVIEW_REQUIRED
       │
       └─► 4. AI Evidence & Authenticity Analysis (AiEvidenceAnalyzer -> GeminiVisionApiClient)
               ├── Relevant & High Confidence (>=0.70) & Low Fraud Risk ──► Satisfies AI signal
               ├── Irrelevant / Low confidence (<0.70) ──────────────────► REVIEW_REQUIRED
               ├── Suspected AI-generated / Manipulated / Recapture ────► REVIEW_REQUIRED
               └── Provider error / timeout / rate limit ────────────────► REVIEW_REQUIRED
       │
       ▼
Composite Verification Decision
       ├── All signals satisfied ───────► VERIFIED ──► Award Green Points + Check Challenges
       ├── Inconclusive / AI failure ───► REVIEW_REQUIRED (Admin Queue)
       └── Duplicate / Drift Violation ─► REJECTED (Zero Points)
```

## Gemini Vision Integration & Fraud Hardening

### Abstraction Hierarchy
The system preserves the existing `EvidenceAnalyzer` abstraction:
```text
EvidenceAnalyzer (Interface)
  ├── MockEvidenceAnalyzer (Offline development & unit tests)
  └── AiEvidenceAnalyzer (Production AI analyzer)
        └── VisionApiClient (Interface for external Vision APIs)
              ├── GeminiVisionApiClient (Google Gemini Vision REST API via x-goog-api-key)
              ├── OpenAiVisionApiClient (OpenAI / GPT-4o-mini Vision REST API)
              └── MockVisionApiClient (Deterministic mock client)
```

### Active Model Selection
- Default supported production model: `gemini-3.5-flash-lite` (Google's active Flash multimodal model with JSON mode).
- Configurable dynamically via `AI_MODEL`.

### Two-Dimensional Analysis Framework
The prompt and structured parser enforce two distinct evaluation axes:
1. **Action Relevance**:
   - `relevant`: boolean indicating whether the photograph visually shows the claimed action.
   - `confidence`: numeric float [0.0 - 1.0].
   - `reasoning`: concise rationale for the judgment.
   - `detectedElements`: array of key visual objects recognized in the photo.
2. **Fraud & Authenticity Risk**:
   - `fraudRisk`: `"LOW"`, `"MEDIUM"`, or `"HIGH"`.
   - `possibleAiGenerated`: boolean flag for diffusion artifacts, warped geometry, or synthetic textures.
   - `possibleManipulation`: boolean flag for compositing, cutout borders, cloned areas, or inconsistent lighting.
   - `possibleRecapture`: boolean flag for moiré patterns, screen pixels, or photo-of-screen reflections.
   - `fraudIndicators`: array of specific visual anomaly descriptions.

### AI-Generated Image Limitation & Probabilistic Nature
> [!IMPORTANT]
> Visual fraud and AI-generated image detection are probabilistic. The system does not claim 100% forensic certainty. If visual anomalies are detected, the system safely routes the submission to `REVIEW_REQUIRED` for human campus administrator review rather than issuing an automated hard rejection.

### Anti-Prompt-Injection & Security
- Action titles, categories, and descriptions are sanitized and enclosed within `<action_context>` boundary tags.
- The model is explicitly instructed that content inside `<action_context>` is untrusted catalog data and cannot override system verification rules.
- The API key is sent via the `x-goog-api-key` HTTP header, keeping credentials completely out of request URLs, proxies, and access logs.

### Privacy & Data Flow
- **Transmitted to Gemini**: Sanitized image bytes (JPEG/PNG), MIME type, action title, action category, and verification instructions.
- **Never transmitted**: User IDs, student names, emails, passwords, JWT tokens, device identifiers, or GPS coordinates.

## Configuration

```properties
# AI Evidence Verification Configuration
carbontrack.ai.enabled=${AI_ENABLED:false}
carbontrack.ai.provider=${AI_PROVIDER:mock}
carbontrack.ai.api-key=${AI_API_KEY:}
carbontrack.ai.model=${AI_MODEL:gemini-3.5-flash-lite}
carbontrack.ai.base-url=${AI_BASE_URL:}
carbontrack.ai.timeout-seconds=${AI_TIMEOUT_SECONDS:10}
carbontrack.ai.timeout-ms=${AI_TIMEOUT_MS:10000}
carbontrack.ai.confidence-threshold=${AI_CONFIDENCE_THRESHOLD:0.70}
```

Environment variables:
- `AI_ENABLED`: `true` or `false` (default: `false`)
- `AI_PROVIDER`: `gemini`, `openai`, or `mock`
- `AI_API_KEY`: API key for the chosen provider (untracked in local `.env`)
- `AI_MODEL`: Model name (default: `gemini-3.5-flash-lite`)
- `AI_TIMEOUT_MS`: HTTP timeout in milliseconds (default: 10000)
- `AI_CONFIDENCE_THRESHOLD`: Confidence threshold float (default: 0.70)
